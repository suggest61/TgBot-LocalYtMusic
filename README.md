# Music Downloader Bot

## Запуск

```bash
pip install -r requirements.txt
# ffmpeg должен быть установлен в системе (apt install ffmpeg / brew install ffmpeg)

export BOT_TOKEN="твой_токен_от_BotFather"
export WHITELIST="123456789,987654321"   # опционально, ID через запятую

python main.py
```

## Что добавилось по сравнению с исходной версией

- **Меню на кнопках** (`/start`): настройки, история, помощь — не нужно помнить команды.
- **Настройки формата и качества** (`/settings`): MP3 / Opus / FLAC, 128/192/320 kbps,
  сохраняются на пользователя между сессиями (файл `data/users.json`).
- **Плейлисты**: ссылка на плейлист/альбом (YouTube, SoundCloud и т.д.) разворачивается
  в отдельные треки и скачивается по очереди, с ограничением `MAX_PLAYLIST_SIZE` (по умолчанию 50).
- **Несколько ссылок в одном сообщении**: просто пришли их одну под другой — бот скачает всё
  по очереди и пришлёт итог (сколько успешно, сколько с ошибкой).
- **Поиск по названию** (`/search название`): если нет ссылки — бот ищет на YouTube и
  предлагает выбрать трек кнопкой.
- **История** (`/history`): последние 20 скачанных треков.
- **Ограничение параллельных загрузок**: общий семафор на весь бот, чтобы 5 человек
  одновременно не положили сервер по CPU/сети.
- **Проверка размера файла** перед отправкой (лимит Telegram Bot API ~50 МБ).

## Скачивание видео (отдельно от бота)

Бот качает только аудио. Для скачивания видео целиком есть отдельный
самостоятельный скрипт `video_downloader.py` — без Telegram, работает локально
из консоли:

```bash
pip install yt-dlp
# ffmpeg должен быть установлен в системе

python video_downloader.py https://youtu.be/XXXXXXXXXXX
python video_downloader.py URL1 URL2 URL3 -q 1080          # несколько ссылок, качество 1080p
python video_downloader.py "https://youtube.com/playlist?list=XXXX" -o my_videos
python video_downloader.py URL --no-playlist                # только это видео, не весь плейлист
```

По умолчанию качество ограничено 720p (флаг `-q`, доступны 360/480/720/1080/2160/best),
файлы сохраняются в `./downloads_video` (флаг `-o`).

## Структура проекта

```
main.py            # точка входа, регистрация роутеров
config.py           # токен, whitelist, форматы/качество, лимиты
storage.py           # JSON-хранилище настроек и истории пользователей
downloader.py        # вся логика yt-dlp: поиск, плейлисты, скачивание аудио
keyboards.py         # inline-клавиатуры
video_downloader.py   # отдельный CLI-скрипт для скачивания видео (без Telegram)
handlers/
  start.py           # /start, /help, главное меню
  settings.py         # /settings, выбор формата/качества
  history.py          # /history
  search.py           # /search
  download.py          # основной хендлер: ловит ссылки и качает аудио
```

## Идеи для дальнейшего развития

Расставил примерно по трудозатратам:

**Просто добавить:**
- Кнопка "Отмена" во время скачивания (через `asyncio.Task.cancel()`).
- Прогресс-бар в процентах во время скачивания одного трека (yt-dlp даёт progress_hooks).
- Троттлинг: не более N запросов от одного юзера в минуту, чтобы не абьюзили бота.
- Команда `/stats` для админа — сколько всего скачано, сколько активных юзеров.
- Кэш по URL: если трек уже качали (кто угодно) — отдавать сохранённый file_id из Telegram
  вместо повторного скачивания (Telegram хранит файлы по file_id, это мгновенно и без нагрузки).

**Средней сложности:**
- Обрезка аудио (задать начало/конец трека) — через ffmpeg `-ss`/`-to`, кнопками "обрезать".
- Определение и подтягивание текста песни (Genius API / lyrics.ovh) — прикреплять к треку.
- Скачивание из Spotify-ссылок: спарсить название трека/плейлиста через Spotify API
  (без DRM-обхода — просто взять метаданные и найти этот же трек на YouTube).
- Video-режим: не только аудио, но и видео (например, клипы) с выбором разрешения.
- SQLite вместо JSON-файла — надёжнее при большом числе пользователей и одновременных записях.

**Более крупные фичи:**
- Web-панель администратора (FastAPI + простая веб-страница) со статистикой и логами —
  это уже был бы отдельный "полноценный GUI" вне Telegram, если он вам нужен помимо бота.
- Docker-образ для быстрого деплоя (Dockerfile + docker-compose с ffmpeg внутри).
- Очередь на Redis/Celery вместо семафора в памяти — если бот вырастет и его будут
  держать на нескольких инстансах одновременно.
- Инлайн-режим бота (`inline_query`) — искать и слать треки прямо из любого чата в Telegram,
  не заходя в диалог с ботом.
